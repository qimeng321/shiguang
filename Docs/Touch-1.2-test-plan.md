# 拾光号 iOS 触控测试版 1.2 — 设计、限制与手工回归

**仅供源代码审查和后续真机测试**。基于正式版 1.03 Build 112，独立分支 `test/1.2-smart-hover-gestures-source`。用户本次明确要求**不生成 IPA**；因此未进行 Xcode iOS Release 编译和真实游戏运行测试。

## 变更范围

1. 默认关闭的「智能悬停」模式，位于游戏右上角三点菜单。与原「触屏延迟」模式互斥。
2. 仅在玩家触碰 Flash 游戏画布且未触摸输入框、键盘或菜单时处理手势：短按 → 一次正常鼠标左键点击；静止长按 420ms → 模拟鼠标进入/移动，不产生 `pointerdown`、`pointerup`，用于显示 NoNo 的悬停圆环；移动超过 12 px → 改成普通拖动并在松手时结束。
3. 多指触碰时取消未完成的触控，阻止误双击；进入后台、页面关闭、关闭模式时清理计时器与按键状态。
4. 虚拟鼠标触控板新增「双击」「右键」按钮。右键使用 `PointerEvent button=2`，Ruffle 与游戏本身不保证对此有特殊响应。
5. 维持原登录、NoNo 主页面单击、键盘、地图、PVM、socketProxy、画质、帧率等功能，不修改任何 .srom 或 SWF。
6. 独立测试包标识预设为 `cn.shiguanghao.launcher.smartbeta`（1.2.0 Build114），正式版 `cn.shiguanghao.launcher` 原样保留。若将来生成 IPA，iOS 沙盒将独立，因此须给测试版单独导入完整游戏包。

## 重要限制

- **无 NoNo 坐标识别**：玩家需要长按 NoNo 当前显示位置。它移动后无法自动追踪；若悬停触发时菜单消失，需要重新长按或使用精准鼠标。
- **没有新增双指缩放**：Flash 尺寸/Canvas 光标坐标系统会受缩放影响，避免在这版引入偏移。
- **不使用 SWF 修改**：这里测试的是网页向 Ruffle 内层 Canvas 派发 PointerEvent 的方式。实际 NoNo 是否在松手后继续保持圆环、以及点击圆环按钮是否正确，必须在真实 iPhone/iPad 上检验。
- **兼容的短按语义未完全证明**：Node 模拟器可验证事件数量与顺序，不能代替 Flash 内部 UI 事件行为。

## 真机回归建议

- 默认关闭智能悬停时，原版单击 NoNo 打开主页、地图拖动和战斗按钮点击正常。
- 开启模式，短按 NoNo 仍进入主页；长按 NoNo 420ms 后显示圆环且不跳主页；松手后点各圆环图标。
- 在 NoNo 跟随角色移动时长按它当前的位置，重复 10 次，检查圆环出现率与误打开主页率。
- 在地图内大幅拖动与小幅手指抖动，验证拖动不误识别为长按。
- 在背包、技能、登录输入区域测试短按/长按，并验证手机键盘未被阻断。
- 双指触碰后回到单指，检查没有残留点击或拖动。
- 用虚拟鼠标执行双击和右键，测试是否被 Ruffle / 游戏接受。
- 切换画面方向、切出 App、刷新游戏、从智能悬停切换回触屏延迟，检查未残留按下状态。
- 失败时通过首页「反馈问题」导出 diagnostics.txt，附当前步骤和录屏。

## 已完成的非真机测试

使用 Node 执行 `Patches/test-direct-touch.js` 与 `Patches/test-smart-touch.js`，覆盖默认关闭、短按、420ms 无点击悬停、拖动、取消、多指防误触、切换清理、虚拟鼠标双击/右键；使用 Swift 前端语法解析和内嵌 JavaScript 语法检查。它们仅证明相应代码路径和模拟事件行为，不代表 Xcode 编译、真实 NoNo 效果已经验证。
