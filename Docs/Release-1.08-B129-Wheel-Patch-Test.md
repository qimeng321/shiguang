# 拾光号 iOS 1.08 (Build129) / 手机补丁 1.0.7-test

**状态：实验性修复候选，尚未通过实际游戏内验证。请保留正式版1.07的安装包。**

## 目标
在 iOS Ruffle Stable 0.7.1 与 2026-11-12 Nightly 中，命运之轮“通过”或“宝箱”非战斗切层后，服务器成功回复 CMD2452，但下一轮卡牌界面未出现。Windows Ruffle 能正常运行。两个 iOS 引擎对照说明更换引擎本身不足以解决。

## 1.08 启动器改动
- 版本 1.0.8 / Build129，首页显示“测试版 1.08”。
- 保留 1.07 的 Bundle ID `cn.shiguanghao.launcher`，以允许同证书覆盖安装保留已导入的游戏资源；安装前请自行做好备份。
- 保留旧手机补丁对 `resource/` 的白名单，不允许任意覆盖代码、登录、配置或引擎。
- **唯一新增**可覆盖的核心代码路径是 `dll/SGCore.swf`。补丁必须提供 `targetRevision` 和 `originalSHA256["dll/SGCore.swf"]`，导入时及每次启动游戏时都要校验原始游戏文件 SHA-256。不匹配拒绝安装/启用。
- 仍然使用 HTTP 影子层提供补丁，不写回游戏原始文件。安装具有旧版备份及失败原子回滚；可通过“清除手机补丁”撤回。
- 1.07 正式版源代码未改动，构建只在 `test/shiguang-1.08-b129-wheelpatch` 分支进行。

## 安装与验证
1. 保留已知可用的 1.07 IPA、当前 .srom 和旧手机补丁。1.08 用相同证书覆盖安装时通常保留 App 数据，但仍建议在可能的情况下备份。
2. 确认游戏内使用的 2026110801 资源，先直接进入游戏测试 1.08 无补丁状态。
3. 在独立“手机适配补丁”入口导入 `拾光号移动端专项补丁1.0.7-test.sgpatch`；如果提示核心 SHA-256 不匹配，不要跳过校验。
4. 退出游戏后重新进入，确认诊断日志中出现 `[手机补丁] 覆盖游戏资源：dll/SGCore.swf`。
5. 分别测试命运之轮“通过”、“宝箱”、“战斗胜利”、退出及再次进入，注意是否重新出现六张卡牌，是否有重复动画、崩溃、地图或任务栏异常。
6. 如果异常，在启动器中清除手机补丁、退出并重新进入游戏，原版 .srom 核心仍然完整。
7. 将诊断日志和复现路径发送进行对比。不要测试多次重复奖励的行为。

## 安全与兼容
清单格式向后兼容 resource-only 老补丁，核心替换要求原版哈希完全一致。此补丁只支持 2026110801 且原始 SGCore 匹配指定哈希的资源包。原补丁的两个 SWF 来源于旧包；由于新版世界地图与任务图标可能变化，其适配效果仍需要验证。
